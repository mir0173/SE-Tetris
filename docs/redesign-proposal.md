## 1. 목표

중간 평가 피드백은 "PDF를 그대로 구현했다, 현장 반응도 신경 써야 한다"였다. 그래서 기능과 규칙은 그대로 두고, **보이는 것과 손맛**을 바꿔 "진짜 게임" 느낌을 낸다.

1. **일관된 테마**: 모든 화면이 같은 색, 글꼴, 버튼 모양을 쓴다.
2. **블록 디자인**: 글자 하나만 찍던 칸을 입체감 있는 타일로 바꾼다. 글자는 남긴다(2절 참고).
3. **손맛(연출)**: 하드 드롭 흔들림, 줄 삭제 반짝임 강화, 점수 팝업, 레벨 업 표시, 화면 전환, 대전 승리 연출.
4. **조작 안내**: 모든 화면 아래에 사용할 수 있는 키를 표시한다. 1차 요구사항 "다른 키를 쓰면 화면에 표시"를 보완하는 일이다.

**추천: B를 기본으로 하고, 연출은 시안과 상관없이 공통으로 넣는다.** 시연 투표는 첫인상의 영향이 크다. B의 빛번짐은 JavaFX `DropShadow`/Canvas 그림자로 그대로 만들 수 있다. 성능이 걱정되면 빛번짐을 현재 블록과 테두리에만 쓴다. 어느 쪽이 좋은지 모르겠다면 A의 블록 + B의 배경처럼 섞는 것도 가능하다.

글꼴은 모두 OFL(무료 배포 허용) 라이선스라 `src/main/resources/fonts`에 넣어 함께 배포할 수 있다. 1개당 약 0.1~2MB다.

## 5. 개발 방식

1. **테마를 한 곳에 모은다**
   - 색은 `Theme` 클래스(Canvas용 색 상수), 버튼과 글자 모양은 `theme.css`(JavaFX CSS) 하나에 둔다.
   - 지금은 색이 `JavaFxGameView` 같은 화면 클래스 안에 흩어져 있다.
2. **블록 그리기를 분리한다**
   - `BlockRenderer`(타일, 고스트, 넘어온 줄, 아이템 글자)를 만들어 1인·대전·P2P 화면이 같이 쓴다.
3. **글꼴을 번들한다**
   - `Font.loadFont`로 resources의 TTF 파일을 불러온다.
   - 불러오기에 실패하면 기본 글꼴을 쓴다.
4. **연출은 시간 기반**
   - `Timeline`이나 `AnimationTimer`로 그림만 바꾼다.
   - 게임 규칙(`Game`)은 건드리지 않아서 입력 반응과 점수에 영향이 없다.
5. **테스트**
   - 노드 ID(`#game-board`, `#garbage-preview` 등)는 유지한다. 그러면 대부분의 테스트가 그대로 통과한다.
   - 픽셀 색을 직접 비교하는 테스트(`JavaFxGameViewTest`, `JavaFxGameViewGarbagePreviewTest`, `JavaFxBattleViewTest`)는 `Theme` 상수를 참조하도록 바꾼다.
   - 버튼 글자로 찾는 테스트(시작 메뉴 등)는 문구를 바꾸면 함께 고친다.
6. **PR 순서 제안** (각 PR마다 전체 테스트 통과 + 2절 표 확인)
   1. 테마 기반: `Theme`, `theme.css`, 글꼴, 키 안내 바. 화면 모양만 바뀜
   2. 게임 화면: `BlockRenderer`, 사이드바 패널, 고스트, 일시정지
   3. 메뉴·설정·스코어보드·대전 키 설정
   4. 대전·P2P 화면
   5. 연출: 흔들림, 팝업, 카운트다운, 화면 전환, 게임 오버 패널
   6. (선택) 효과음·배경음악
7. **충돌 주의**
   - 팀장이 `JavaFxGameView`, `JavaFxP2pGameView`를 자주 고친다.
   - PR 1~2를 먼저 빨리 merge하고, 그 전에 팀에 "화면 파일 리디자인 중"이라고 알린다.
